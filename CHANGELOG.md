## 1.0.0 (2026-04-25)

### ⚠ BREAKING CHANGE

* **Kafka:** Complete redesign of Kafka integration with unified producer/consumer APIs,
decorator-based handlers, and full context propagation.
Legacy messaging patterns and inconsistent event handling have been removed.

✨ Features:
- Unified Kafka abstraction built on KafkaJS
- Decorator-based event handling:
  - @KafkaEventHandler() for consumer registration
  - @KafkaEvent() for topic binding
- Centralized KafkaProducerService:
  - Typed event publishing
  - Standardized event envelope (key, value, metadata)
- Automatic context propagation:
  - traceparent, baggage (OpenTelemetry)
  - tenantId, actorId, requestId (via @omnixys/context)
- Built-in retry & DLQ support:
  - Configurable retry strategies
  - Dead Letter Queue handling (DLQ topics)
- Consumer lifecycle management:
  - Graceful startup/shutdown
  - Batch and single-message processing modes
- Message serialization layer:
  - Safe JSON handling (BigInt support, normalization)
- Header abstraction for cross-service communication
- Integration hooks for observability (tracing spans per message)

⚙️ Improvements:
- Strongly typed event contracts and payloads
- Eliminated boilerplate Kafka consumer/producer setup
- Standardized topic naming and event structure
- Improved resilience with retry and error handling strategies
- Reduced duplication across microservices

🧱 Architecture:
- Modular NestJS integration (KafkaModule)
- Separation of concerns:
  - Producer (publishing)
  - Consumer (handlers via decorators)
  - Context propagation layer
- Pluggable configuration (brokers, clientId, groupId, retry)
- Designed for event-driven microservice architectures

🛑 Removed / Changed:
- Removed ad-hoc KafkaJS usage across services
- Replaced manual consumer wiring with decorator-based system
- Deprecated inconsistent message formats and header handling

📦 Compatibility:
- Requires Node.js >= 20
- Built on KafkaJS v2+
- Fully compatible with:
  - @omnixys/context (request context propagation)
  - @omnixys/observability (distributed tracing)
  - @omnixys/security (event-level validation / policies)
  - @omnixys/cache (idempotency, replay protection, DLQ handling)

consistent integration with distributed system components.

## 1.0.0 (2026-04-16)

### ⚠ BREAKING CHANGE

* **Kafka:** Complete redesign of Kafka integration with unified producer/consumer APIs,
decorator-based handlers, and full context propagation.
Legacy messaging patterns and inconsistent event handling have been removed.

✨ Features:
- Unified Kafka abstraction built on KafkaJS
- Decorator-based event handling:
  - @KafkaEventHandler() for consumer registration
  - @KafkaEvent() for topic binding
- Centralized KafkaProducerService:
  - Typed event publishing
  - Standardized event envelope (key, value, metadata)
- Automatic context propagation:
  - traceparent, baggage (OpenTelemetry)
  - tenantId, actorId, requestId (via @omnixys/context)
- Built-in retry & DLQ support:
  - Configurable retry strategies
  - Dead Letter Queue handling (DLQ topics)
- Consumer lifecycle management:
  - Graceful startup/shutdown
  - Batch and single-message processing modes
- Message serialization layer:
  - Safe JSON handling (BigInt support, normalization)
- Header abstraction for cross-service communication
- Integration hooks for observability (tracing spans per message)

⚙️ Improvements:
- Strongly typed event contracts and payloads
- Eliminated boilerplate Kafka consumer/producer setup
- Standardized topic naming and event structure
- Improved resilience with retry and error handling strategies
- Reduced duplication across microservices

🧱 Architecture:
- Modular NestJS integration (KafkaModule)
- Separation of concerns:
  - Producer (publishing)
  - Consumer (handlers via decorators)
  - Context propagation layer
- Pluggable configuration (brokers, clientId, groupId, retry)
- Designed for event-driven microservice architectures

🛑 Removed / Changed:
- Removed ad-hoc KafkaJS usage across services
- Replaced manual consumer wiring with decorator-based system
- Deprecated inconsistent message formats and header handling

📦 Compatibility:
- Requires Node.js >= 20
- Built on KafkaJS v2+
- Fully compatible with:
  - @omnixys/context (request context propagation)
  - @omnixys/observability (distributed tracing)
  - @omnixys/security (event-level validation / policies)
  - @omnixys/cache (idempotency, replay protection, DLQ handling)

📚 Notes:
This release establishes a standardized event streaming foundation across all
Omnixys services, enabling reliable communication, traceable event flows, and
consistent integration with distributed system components.

### ⚠ BREAKING CHANGE

* **Kafka:** Complete redesign of Kafka integration with unified producer/consumer APIs,
decorator-based handlers, and full context propagation.
Legacy messaging patterns and inconsistent event handling have been removed.

✨ Features:
- Unified Kafka abstraction built on KafkaJS
- Decorator-based event handling:
  - @KafkaEventHandler() for consumer registration
  - @KafkaEvent() for topic binding
- Centralized KafkaProducerService:
  - Typed event publishing
  - Standardized event envelope (key, value, metadata)
- Automatic context propagation:
  - traceparent, baggage (OpenTelemetry)
  - tenantId, actorId, requestId (via @omnixys/context)
- Built-in retry & DLQ support:
  - Configurable retry strategies
  - Dead Letter Queue handling (DLQ topics)
- Consumer lifecycle management:
  - Graceful startup/shutdown
  - Batch and single-message processing modes
- Message serialization layer:
  - Safe JSON handling (BigInt support, normalization)
- Header abstraction for cross-service communication
- Integration hooks for observability (tracing spans per message)

⚙️ Improvements:
- Strongly typed event contracts and payloads
- Eliminated boilerplate Kafka consumer/producer setup
- Standardized topic naming and event structure
- Improved resilience with retry and error handling strategies
- Reduced duplication across microservices

🧱 Architecture:
- Modular NestJS integration (KafkaModule)
- Separation of concerns:
  - Producer (publishing)
  - Consumer (handlers via decorators)
  - Context propagation layer
- Pluggable configuration (brokers, clientId, groupId, retry)
- Designed for event-driven microservice architectures

🛑 Removed / Changed:
- Removed ad-hoc KafkaJS usage across services
- Replaced manual consumer wiring with decorator-based system
- Deprecated inconsistent message formats and header handling

📦 Compatibility:
- Requires Node.js >= 20
- Built on KafkaJS v2+
- Fully compatible with:
  - @omnixys/context (request context propagation)
  - @omnixys/observability (distributed tracing)
  - @omnixys/security (event-level validation / policies)
  - @omnixys/cache (idempotency, replay protection, DLQ handling)

consistent integration with distributed system components.

* **Kafka:** Complete redesign of Kafka integration with unified producer/consumer APIs,
decorator-based handlers, and full context propagation.
Legacy messaging patterns and inconsistent event handling have been removed.

✨ Features:
- Unified Kafka abstraction built on KafkaJS
- Decorator-based event handling:
  - @KafkaEventHandler() for consumer registration
  - @KafkaEvent() for topic binding
- Centralized KafkaProducerService:
  - Typed event publishing
  - Standardized event envelope (key, value, metadata)
- Automatic context propagation:
  - traceparent, baggage (OpenTelemetry)
  - tenantId, actorId, requestId (via @omnixys/context)
- Built-in retry & DLQ support:
  - Configurable retry strategies
  - Dead Letter Queue handling (DLQ topics)
- Consumer lifecycle management:
  - Graceful startup/shutdown
  - Batch and single-message processing modes
- Message serialization layer:
  - Safe JSON handling (BigInt support, normalization)
- Header abstraction for cross-service communication
- Integration hooks for observability (tracing spans per message)

⚙️ Improvements:
- Strongly typed event contracts and payloads
- Eliminated boilerplate Kafka consumer/producer setup
- Standardized topic naming and event structure
- Improved resilience with retry and error handling strategies
- Reduced duplication across microservices

🧱 Architecture:
- Modular NestJS integration (KafkaModule)
- Separation of concerns:
  - Producer (publishing)
  - Consumer (handlers via decorators)
  - Context propagation layer
- Pluggable configuration (brokers, clientId, groupId, retry)
- Designed for event-driven microservice architectures

🛑 Removed / Changed:
- Removed ad-hoc KafkaJS usage across services
- Replaced manual consumer wiring with decorator-based system
- Deprecated inconsistent message formats and header handling

📦 Compatibility:
- Requires Node.js >= 20
- Built on KafkaJS v2+
- Fully compatible with:
  - @omnixys/context (request context propagation)
  - @omnixys/observability (distributed tracing)
  - @omnixys/security (event-level validation / policies)
  - @omnixys/cache (idempotency, replay protection, DLQ handling)
